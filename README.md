# sqldb2lite

> **Hybrid SQL Dump to SQLite3 Converter**  
> Powered by `sqlglot` AST parsing, out-of-line foreign key stitching, and streaming bulk data ingestion.

`sqldb2lite` is a standalone, local Python tool designed to convert database dumps (starting with MySQL and PostgreSQL) into clean, fully-functioning SQLite databases—preserving table relationships, primary keys, foreign keys, and indexes without requiring Docker or a running database daemon.

---

## Quick Start

### 1. Installation

Ensure Python 3.10+ is installed, then install dependencies:
```bash
pip install sqlglot pytest
```

### 2. CLI Usage

The source dialect (`-d` or `--dialect`) is **required**:

```bash
# Convert a MySQL dump:
python cli.py path/to/mysql_dump.sql -d mysql -o database.db

# Convert a PostgreSQL dump:
python cli.py path/to/postgres_dump.sql -d postgres -o database.db

# Or if executing as a module:
# python -m sqldb2lite.cli path/to/dump.sql -d mysql -o database.db
```

#### CLI Options:
* `-d, --dialect`: **Required.** Source dialect (`mysql`, `mariadb`, `postgres`, `postgresql`).
* `-o, --output`: Output SQLite file path (defaults to `<dump_name>.db`).
* `-b, --batch-size`: Batch size for streaming data rows (default: `5000`).
* `-q, --quiet`: Suppress verbose summary table.

### 3. Python API Usage

```python
from sqldb2lite import convert_dump_to_sqlite, inspect_sqlite_db

# Convert dump
report = convert_dump_to_sqlite(
    dump_path="samples/mysql/mysql_classicmodels.sql",
    sqlite_db_path="classicmodels.db",
    dialect="mysql"
)

print(f"Total tables: {report['total_tables']}")
print(f"Total rows: {report['total_rows']:,}")
print(f"Total foreign keys: {report['total_foreign_keys']}")
print(f"Violations: {report['fk_violations']}")
```

## Architecture & Directory Structure

`sqldb2lite` uses a pluggable handler architecture. Database-specific quirks (data types, table options, lock commands, dump formats) are isolated into dedicated dialect modules:

```text
sqldb2lite/
├── __init__.py           # Public exports
├── cli.py                # Command-line interface
├── converter.py          # Core pipeline orchestrator
├── dialects/             # Modular dialect handlers
│   ├── base.py           # Abstract Base Class (interface contract)
│   ├── mysql.py          # MySQL/MariaDB handler & streamer
│   └── postgres.py       # PostgreSQL handler & COPY streamer
├── samples/              # Test SQL dumps ONLY
│   ├── mysql/
│   └── postgres/
└── tests/
    ├── sqlite_generated/ # Generated SQLite databases ONLY
    │   ├── mysql/
    │   └── postgres/
    └── test_converter.py # Pytest test suite
```

## Current Limitations

While `sqldb2lite` handles standard schemas, foreign keys, and data streams reliably, users should be aware of the following known constraints:

### 1. Plain-Text SQL Dumps Only (No Binary Dumps)
* **Supported:** Text `.sql` files generated by `mysqldump`, phpMyAdmin, DBeaver, or `pg_dump --format=plain`.
* **Not Supported:** Binary/custom archive dumps (e.g., `pg_restore` `.dump` or `.tar` files, MySQL raw `.ibd` tablespace files). These must first be exported as plain text SQL.

### 2. Server-Specific DDL & Procedural Logic
* **Stored Procedures & Functions:** SQLite does not have a procedural language engine. Stored procedures (`CREATE PROCEDURE`), PL/pgSQL functions (`CREATE FUNCTION ... AS $$ ... $$`), and packages are ignored and omitted.
* **Triggers:** Complex dialect-specific triggers that reference server variables or proprietary functions cannot run in SQLite and are skipped.

### 3. Database Schemas / Namespaces Flattened
* In PostgreSQL, tables often reside in namespaces (e.g. `public.users` or `inventory.items`). SQLite is single-namespace; `sqldb2lite` flattens all tables to the root namespace (e.g., `users`, `items`). Multiple schemas containing tables with identical names will collide.

### 4. Advanced Proprietary Data Types
* **Geometry / GIS:** Spatial types (`GEOMETRY`, `POINT`, `POLYGON`) are cast to standard `TEXT` or `BLOB` because SQLite lacks native spatial indexing without the SpatiaLite C extension.
* **Composite / Custom Domain Types:** Custom Postgres domains or user-defined types (e.g. `CREATE DOMAIN`, `CREATE TYPE`) are converted to SQLite dynamic affinity types (`TEXT` or `NUMERIC`).

### 5. NoSQL & Document Stores Unsupported
* `sqldb2lite` transpile-compiles SQL schemas. It does not parse document/key-value/graph exports (MongoDB BSON/JSON, DynamoDB, Neo4j Cypher, Redis).
